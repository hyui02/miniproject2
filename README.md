# 와인 품질 분류 (DACON) — 미니 프로젝트 2

와인의 이화학적 성분 11개와 종류(레드·화이트)로 품질 등급(3~9)을 분류한다. 평가 지표는 정확도(Accuracy)이며, 최종 모델은 리더보드 **0.711**을 기록하였다.

## 분석 흐름: 무엇을 보았고, 그래서 무엇을 했는가

### 1. 데이터의 특성 → 검증 방식
- 학습 데이터 5,497행 중 성분이 완전히 같은 행이 858개(15.6%)이고, 성분이 같으면 품질도 항상 같다.
- 같은 와인이 학습과 검증에 나뉘어 들어가면 모델이 정답을 외워 점수가 부풀려진다. 실제로 일반 5-Fold 교차검증은 0.6765였지만, 같은 성분의 와인을 한 묶음으로 둔 그룹 교차검증은 0.5758이었다.
- **그래서** 모든 모델 비교는 그룹 교차검증(StratifiedGroupKFold)으로 하였다.

### 2. 테스트와 학습의 관계 → 예측 방식
- 테스트 1,000행 중 303행은 학습 데이터와 성분이 같다.
- **그래서** 이 303행은 학습 데이터의 품질을 그대로 쓰고, 나머지 697행만 모델로 예측한다. 리더보드 점수는 사실상 이 697행의 정확도로 결정된다.

### 3. 품질과 성분의 관계 → 모델 선택
- 등급이 높을수록 도수는 오르고 밀도·휘발성산·염화물은 내려가지만, 5·6·7등급의 성분 분포는 크게 겹친다. 품질 점수가 사람의 시음 평가이기 때문이다.
- 한 변수의 기준선으로 등급을 나눌 수 없으므로, 여러 성분의 조합을 학습하는 트리 앙상블이 적합하다. 꼬리가 긴 분포와 이상치도 값의 순서만 쓰는 트리 모델에는 영향이 작아 변환하지 않았다.
- **그래서** 랜덤 포레스트, Extra Trees, 그리고 세 트리 모델(랜덤 포레스트·Extra Trees·CatBoost)의 확률을 로지스틱 회귀로 결합한 스태킹을 평균한 모델을 만들었다 → 리더보드 **0.709**.

### 4. 0.709 이후의 정체 → 원리가 다른 모델 추가
- 0.709 이후 약 100가지 변형을 시험해 교차검증 기준을 넘은 15개 파일을 제출했으나 모두 0.697~0.708이었다.
- 원인은 두 가지였다. 성분이 거의 같은 와인끼리도 등급이 같은 비율이 41~67%에 그쳐 라벨의 변동이 컸고, 트리 계열 모델들은 같은 행에서 함께 틀려 섞어도 새 정보가 더해지지 않았다.
- **그래서** 트리와 학습 원리가 다른 사전학습 표 기초모델 TabICL을 더하였다. TabICL은 단독 정확도가 0.709 모델과 비슷하면서도 0.709와 다르게 예측하는 행이 더 많아, 서로의 오답을 보완한다.
- 0.25 비중으로 섞으면 0.709의 판단은 대부분 유지되고 확신이 낮은 경계 행만 바뀐다. 그룹 교차검증에서 0.709 대비 +0.0042(분할 3가지 모두 상승), 리더보드 **0.711**이었다.

## 실행 방법

제출 파일과 똑같은 결과는 Apple 칩 맥북에서 아래 순서로 실행해야 나온다. Intel 계열 CPU(예: Google Colab)에서는 트리 모델의 학습 계산이 미세하게 달라 경계의 몇 행이 바뀐다(Colab 실행 결과 0.708).

```bash
python3.14 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/pip install notebook -c requirements.txt
.venv/bin/jupyter notebook
```

- `02_model_0711.ipynb`를 열어 모든 셀을 실행한다(약 4분). 마지막 셀의 품질별 개수가 {4: 7, 5: 354, 6: 503, 7: 125, 8: 11}이면 0.711 제출 파일과 같다.
- 대회 데이터는 저장소에 포함하지 않았으며, `common.py`가 처음 실행할 때 내려받는다.
